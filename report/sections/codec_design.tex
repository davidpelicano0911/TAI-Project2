\section{Codec Design}
\label{sec:codecs}

All three codecs share the same high-level pipeline: parse the raw big-endian
16-bit image; apply a spatial predictor $\hat{p}$; zigzag-encode the signed
residual $r = \text{pixel} - \hat{p}$ as an unsigned symbol
$z = 2r$ if $r\ge0$, $z = -2r-1$ otherwise; entropy-code the result.
Zigzag maps small-magnitude residuals — which are the common case after a
good prediction — to small unsigned integers, concentrating the symbol
distribution near zero regardless of sign.

% ── prism-block ───────────────────────────────────────────────────────────────
\subsection{prism-block: Speed-Focused}
\label{sec:speed}

\paragraph{Partitioning and parallelism.}
The image is split into horizontal bands of 150 rows each (10 bands for
$1500\times1500$). Bands are compressed independently; a shared
\texttt{std::atomic<int>} counter distributes bands to threads via
\texttt{fetch\_add}, achieving lock-free load balancing.

\paragraph{Predictor.}
Each pixel is predicted by the \emph{Gradient-Adjusted Prediction} (GAP)
function of its three decoded neighbours: left ($W$), above ($N$),
and above-left ($NW$). Horizontal and vertical gradients are estimated as
$d_h = |W - NW|$ and $d_v = |N - NW|$. When one gradient dominates
($d_h > 2d_v$ or $d_v > 2d_h$), the perpendicular neighbour is used
directly; otherwise a gradient-weighted blend is computed and clamped:
\[
  \hat{p} = \operatorname{clamp}\!\left(
    \frac{(d_v+1)\,W + (d_h+1)\,N}{d_v+d_h+2},\;
    \min(W,N),\;\max(W,N)\right).
\]
This predictor handles edges and flat regions without a mode switch.

\paragraph{Entropy coding.}
After zigzag encoding, each 16-bit symbol $z$ is split into
$z_h = z \gg 8$ (high byte) and $z_l = z\;\&\;0\!\mathrm{xFF}$ (low byte).
Both bytes are coded with a carry-based range coder backed by adaptive
Fenwick-tree models. $z_h$ uses a single shared model.
$z_l$ is conditioned on the magnitude of the two preceding residuals:
\[
  c = \operatorname{bin}(|\hat{r}_W| + |\hat{r}_N|),
\]
yielding eight context models whose bin boundaries are
$\{0\},\{1\text{--}2\},\{3\text{--}8\},\{9\text{--}32\},
\{33\text{--}64\},\{65\text{--}128\},\{129\text{--}512\},\{>512\}$.
Each model halves all counts when the running total reaches $2^{16}$,
tracking distribution shifts adaptively within a band.

% ── HAIS ──────────────────────────────────────────────────────────────────────
\subsection{HAIS: Balanced}
\label{sec:balanced}

\subsubsection*{Dimension Inference and Block Selection}
HAIS accepts optional width/height arguments; otherwise it infers dimensions
from the file size by trying the integer square root first, then a list of
common astronomical sensor widths (1500, 2048, 4096, \ldots).
It then selects the largest block side $b\le512$ that divides both $W$ and $H$
exactly and yields at least four blocks. For $1500\times1500$ this gives
$b=500$, producing a $3\times3$ grid of nine blocks of 500$\times$500 pixels.

\subsubsection*{Predictive Modes}
For each block, HAIS evaluates five candidate predictors and retains the one
with the lowest estimated coding cost (defined below).

\begin{description}[leftmargin=2em, labelindent=0em]
  \item[Mode~0 (raw)] Symbols are raw pixel values; no prediction.
  \item[Mode~1 (avg)] $\hat{p} = \lfloor(W + N + NW + 1)/3\rfloor$.
  \item[Mode~3 (gmean)] $\hat{p} = \bar{g}$, the global image mean computed
    once before blocking. Removes the bias pedestal in all frames.
  \item[Mode~4 (LS-4)] OLS with features $(W, N, NW, 1)$ per block via
    Gauss-Jordan; four float32 weights (16\,B) stored in the block header.
  \item[Mode~6 (LS-5)] Extends Mode~4 with $NE$ and $NN$; five weights
    (20\,B). Both LS modes use the block's own pixels — no external training.
\end{description}

The mode selection criterion penalises stored weights:
\[
  \text{cost}_m = H(\mathrm{hi}_8) + H(\mathrm{lo}_8)
                + \frac{8\,\delta_m}{n_{\text{pix}}},
\]
where $H(\cdot)$ is empirical byte entropy and
$\delta_m \in \{0,0,0,16,20\}$\,B is the weight header size.

\subsubsection*{Entropy Coding: FSE/tANS}
Residuals are split into a high-byte stream (\texttt{hi}) and a low-byte
stream (\texttt{lo}), each coded independently with Finite State
Entropy~\cite{collet2013fse}.

The FSE table has $\text{SCALE}=2^{16}=65536$ states. Raw symbol counts
are normalised to sum to SCALE (with a minimum frequency of 1 for observed
symbols) and spread deterministically using Collet's step formula:
$\text{step} = (\text{SCALE}\gg1) + (\text{SCALE}\gg3) + 3$.
The encoder processes symbols in reverse, emitting variable-length
transition bits stored in a \texttt{BitWriter}; the decoder reads the
two-byte final state and reconstructs symbols in forward order.

The frequency table is serialised in one of three compact formats:
\emph{single-symbol} (flag \texttt{0x01}, 2\,B total) when all values are
identical; \emph{sparse} (flag byte $= \text{nnz} \in [2,254]$, followed by
$\text{nnz}\times5$\,B symbol--frequency pairs); or \emph{dense}
(flag \texttt{0x00}, $256\times4$\,B) when all 255--256 symbols appear.

\subsubsection*{Context FSE}
Because the high byte of a small residual is almost always zero, the lo8
distribution differs substantially depending on whether $\mathrm{hi}=0$.
When the fraction of zero high bytes falls between 2\% and 98\%, HAIS
builds two conditional lo8 streams — $\texttt{lo\_zero}$
(pixels with $\mathrm{hi}=0$) and $\texttt{lo\_nonzero}$ — and uses the
three-stream layout only if its compressed size is strictly smaller than the
two-stream baseline. The high-byte stream is encoded once and shared between
both candidate payloads. Bit~7 of the mode byte signals the active layout.

\subsubsection*{Parallel Execution}
Blocks are dispatched to a thread pool via a single
\texttt{std::atomic<int>} counter with \texttt{fetch\_add}, writing results
into pre-allocated per-block slots with no mutex required.
