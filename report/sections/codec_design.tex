\section{Codec Design}
\label{sec:codecs}

All three codecs share the same high-level pipeline: parse the raw big-endian
16-bit image; apply a spatial predictor $\hat{p}$; zigzag-encode the signed
residual $r = \text{pixel} - \hat{p}$ as an unsigned symbol
$z = 2r$ if $r\ge0$, $z = -2r-1$ otherwise; entropy-code the result.
Zigzag maps small-magnitude residuals — which are the common case after a
good prediction — to small unsigned integers, concentrating the symbol
distribution near zero regardless of sign.

% ── prism-block ───────────────────────────────────────────────────────────────
\subsection{prism-block: Speed-Focused}
\label{sec:speed}

The design of prism-block centres on one principle: every horizontal strip of
150 rows is entirely self-contained, so any number of strips can be compressed
simultaneously without coordination. A shared \texttt{std::atomic<int>} counter
distributes work to a thread pool via \texttt{fetch\_add}, achieving lock-free
load balancing with no mutex overhead. Figure~\ref{fig:prismblock} illustrates
the full pipeline.

\begin{figure}[h]
  \centering
  \includegraphics[width=\linewidth]{figs/fast_diagram.png}
  \caption{End-to-end pipeline of prism-block. The image is partitioned into
  horizontal strips processed in parallel; within each strip every pixel
  follows the same predict -- residualise -- zigzag -- split -- encode path.}
  \label{fig:prismblock}
\end{figure}


Within each strip, pixels are predicted using the \emph{Gradient-Adjusted
Prediction} (GAP) function of three causal neighbours: left ($W$), above ($N$),
and above-left ($NW$). GAP estimates horizontal and vertical gradients as
$d_h = |W - NW|$ and $d_v = |N - NW|$, and when one gradient strongly
dominates ($d_h > 2d_v$ or $d_v > 2d_h$) it falls back to the perpendicular
neighbour directly. Otherwise it computes a gradient-weighted blend clamped to
the range $[\min(W,N),\max(W,N)]$:
\[
  \hat{p} = \operatorname{clamp}\!\left(
    \frac{(d_v+1)\,W + (d_h+1)\,N}{d_v+d_h+2},\;
    \min(W,N),\;\max(W,N)\right).
\]
This single formula handles both smooth regions and edges without any
explicit mode switch.

The signed residual is zigzag-mapped to a 16-bit unsigned symbol and split
into a high byte $z_h = z \gg 8$ and a low byte $z_l = z\;\&\;0\text{xFF}$.
Both are coded with a carry-propagation range coder backed by adaptive
Fenwick-tree frequency models. The high byte uses one shared model across all
pixels in the strip, while the low byte selects among eight context models
conditioned on the sum of the two neighbouring residual magnitudes:
\[
  c = \operatorname{bin}(|\hat{r}_W| + |\hat{r}_N|),
\]
with bin boundaries $\{0\},\{1\text{--}2\},\{3\text{--}8\},\{9\text{--}32\},
\{33\text{--}64\},\{65\text{--}128\},\{129\text{--}512\},\{>512\}$.
Each model halves all counts when the running total reaches $2^{16}$, keeping
the frequency estimates responsive to distribution shifts within a strip.

% ── HAIS ──────────────────────────────────────────────────────────────────────
\subsection{HAIS: Balanced}
\label{sec:balanced}

\subsubsection*{Block Selection}
HAIS requires explicit $n\_rows$ and $n\_cols$ arguments, which are stored in
the compressed header so the decoder needs no additional input.
It then selects the largest block side $b\le512$ that divides both $W$ and $H$
exactly and yields at least four blocks. For $1500\times1500$ this gives
$b=500$, producing a $3\times3$ grid of nine blocks of 500$\times$500 pixels.

\subsubsection*{Predictive Modes}
For each block, HAIS evaluates five candidate predictors and retains the one
with the lowest estimated coding cost (defined below).

\begin{description}[leftmargin=2em, labelindent=0em]
  \item[Mode~0 (raw)] Symbols are raw pixel values; no prediction.
  \item[Mode~1 (avg)] $\hat{p} = \lfloor(W + N + NW + 1)/3\rfloor$.
  \item[Mode~3 (gmean)] $\hat{p} = \bar{g}$, the global image mean computed
    once before blocking. Removes the bias pedestal in all frames.
  \item[Mode~4 (LS-4)] OLS with features $(W, N, NW, 1)$ per block via
    Gauss-Jordan; four float32 weights (16\,B) stored in the block header.
  \item[Mode~6 (LS-5)] Extends Mode~4 with $NE$ and $NN$; five weights
    (20\,B). Both LS modes use the block's own pixels — no external training.
\end{description}

The mode selection criterion penalises stored weights:
\[
  \text{cost}_m = H(\mathrm{hi}_8) + H(\mathrm{lo}_8)
                + \frac{8\,\delta_m}{n_{\text{pix}}},
\]
where $H(\cdot)$ is empirical byte entropy and
$\delta_m \in \{0,0,0,16,20\}$\,B is the weight header size.

\subsubsection*{Entropy Coding: FSE/tANS}
Residuals are split into a high-byte stream (\texttt{hi}) and a low-byte
stream (\texttt{lo}), each coded independently with Finite State
Entropy~\cite{collet2013fse}.

The FSE table has $\text{SCALE}=2^{16}=65536$ states. Raw symbol counts
are normalised to sum to SCALE (with a minimum frequency of 1 for observed
symbols) and spread deterministically using Collet's step formula:
$\text{step} = (\text{SCALE}\gg1) + (\text{SCALE}\gg3) + 3$.
The encoder processes symbols in reverse, emitting variable-length
transition bits stored in a \texttt{BitWriter}; the decoder reads the
two-byte final state and reconstructs symbols in forward order.

The frequency table is serialised in one of three compact formats:
\emph{single-symbol} (flag \texttt{0x01}, 2\,B total) when all values are
identical; \emph{sparse} (flag byte $= \text{nnz} \in [2,254]$, followed by
$\text{nnz}\times5$\,B symbol--frequency pairs); or \emph{dense}
(flag \texttt{0x00}, $256\times4$\,B) when all 255--256 symbols appear.

\subsubsection*{Context FSE}
Because the high byte of a small residual is almost always zero, the lo8
distribution differs substantially depending on whether $\mathrm{hi}=0$.
When the fraction of zero high bytes falls between 2\% and 98\%, HAIS
builds two conditional lo8 streams — $\texttt{lo\_zero}$
(pixels with $\mathrm{hi}=0$) and $\texttt{lo\_nonzero}$ — and uses the
three-stream layout only if its compressed size is strictly smaller than the
two-stream baseline. The high-byte stream is encoded once and shared between
both candidate payloads. Bit~7 of the mode byte signals the active layout.

\subsubsection*{Parallel Execution}
Blocks are dispatched to a thread pool via a single
\texttt{std::atomic<int>} counter with \texttt{fetch\_add}, writing results
into pre-allocated per-block slots with no mutex required.

% ── APEX ──────────────────────────────────────────────────────────────────────
\subsection{APEX: Compression-Focused}
\label{sec:compression}

\subsubsection*{Two-Tier Architecture}
APEX separates orchestration from compression. The outer \texttt{compress}
binary runs the inner \texttt{range\_compress} engine eight times with block
sizes $\{250, 300, 400, 500, 750, 1000, 1500, 2000\}$ pixels in parallel,
retains the smallest result, and wraps it with a 5-byte \texttt{APX2} magic
header. The corresponding \texttt{decompress} / \texttt{range\_decompress}
pair inverts the process. This exhaustive search over block sizes incurs extra
compression time but requires no tuning per image.

\subsubsection*{Predictor Competition}
For each block, APEX evaluates ten candidate predictors:

\begin{description}[leftmargin=2em, labelindent=0em]
  \item[Mode~0 (raw)] No prediction; symbols are raw pixel values.
  \item[Mode~1 (avg)] $\hat{p} = \lfloor(W + N + NW + 1)/3\rfloor$.
  \item[Mode~3 (gmean)] $\hat{p} = \bar{g}$, global image mean; removes bias pedestal.
  \item[Mode~7 (GAP)] Gradient-adjusted prediction: selects among $W$, $N$, and
    $W+N-NW$ based on the local horizontal and vertical gradient magnitudes.
  \item[Mode~8 (MED)] JPEG-LS median predictor: $\hat{p} = \mathrm{median}(W, N, W+N-NW)$.
  \item[Mode~4 (LS-4)] OLS with features $(W,N,NW,1)$; 4 float32 weights (16\,B overhead).
  \item[Mode~6 (LS-5)] Adds $NE$ and $NN$; 5 weights (20\,B overhead).
  \item[Mode~9 (LS-6)] OLS with $(W, N, NW, WW, NN, 1)$; 6 weights (24\,B overhead).
    The second-order neighbours $WW$ and $NN$ capture slowly varying ramps.
  \item[Mode~10 (LS-16)] 16-weight OLS spanning 4 pixels to the left, 7 pixels
    in the row above (centred), 2 pixels two rows above, and a bias term
    (64\,B overhead). Exploits long-range spatial structure in science frames.
  \item[Mode~11 (LS-24)] 24-weight OLS extending LS-16 with 5 pixels to the left,
    9 pixels in the row above, 5 pixels two rows above, and 4 pixels three rows
    above (96\,B overhead). Captures wider spatial correlations.
\end{description}

All LS weights are solved per block via Gauss-Jordan elimination on the
$N\times N$ normal equations; no external training data are required.
Border pixels where the full neighbourhood is unavailable fall back to GAP.

\subsubsection*{Context Modes and Block Competition}
Each 16-bit zigzag residual is encoded byte-by-byte: first the high byte
($z_h$), then the low byte ($z_l$). Six context strategies are tried,
combining hi-byte and lo-byte conditioning:
\begin{itemize}
  \item \textbf{ctx~0}: single hi model; single lo model.
  \item \textbf{ctx~1}: single hi model; four lo models keyed by
    $z_h \in \{0\},\{1\text{--}2\},\{3\text{--}8\},\{>8\}$.
  \item \textbf{ctx~2}: single hi model; 256 lo models (one per $z_h$ value).
  \item \textbf{ctx~3--5}: same lo conditioning as ctx~0--2, but the hi byte
    is coded with \emph{four} models conditioned on the previous hi byte
    $z_h^{(t-1)}$ using the same four-bin scheme. This order-1 hi context
    exploits spatial runs of similarly sized residuals.
\end{itemize}
Every block is compressed under all $10 \times 6 = 60$ mode/context
combinations; the combination producing the smallest byte count is
stored. Each block header records the chosen \texttt{mode} (1\,B) and
\texttt{ctx\_mode} (1\,B) so the decoder can reproduce the exact prediction
and model layout without side information.

\subsubsection*{Entropy Coding: Adaptive Range Coder}
APEX uses an LZMA-style range coder with a 32-bit range register and a
64-bit low accumulator. Carry propagation is handled by a cache/pending
chain: bytes whose top nibble is \texttt{0xFF} are held until a carry either
flushes them as \texttt{0x00} or confirms them as \texttt{0xFF}.
Renormalisation triggers when $\text{range} < 2^{24}$, emitting one output
byte and shifting the range left by 8.

The probability model is a 256-symbol adaptive Fenwick tree. Frequencies are
initialised uniformly at 1. After each symbol, the count is incremented in
$O(\log 256)$ time. When the running total reaches $2^{16}$, all frequencies
are halved (minimum 1) and the tree is rebuilt, implementing a sliding-window
aging mechanism that keeps the model responsive to local distribution shifts.
